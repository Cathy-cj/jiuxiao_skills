# 从 courseware.json 生成课件关联、学习目标、方法和开场

## 读取范围

只处理按 [schema.md](schema.md)「班型取舍」确定要上传的班型（配星齐全的连续前缀）。对这些班型，读取其两个配星星级目录里的 `courseware.json`，`lesson_data` 恰好写这两条。每个关联项只写目录名：

```json
{ "courseware_num": "<星级文件夹名>" }
```

不要使用 JSON 顶层 `id`，不要读取 `nodes[]`，也不要以任何其他课节补星。`learning_objective` 与 `core_method` 都只从这两份 `courseware.json` 生成。

## `learning_objective`

每个上传的班型都必须写。这是学生学完本班两份课件后应达到的目标，不是解题步骤（步骤归 `core_method`）。

句式只参照 `class示例.json` 的 B 班，**不得照抄其课文**：

```text
理解分数乘法的意义，学会用图形表示分数乘法,学会比较分数单位的大小。
```

硬性形式：

- 一条中文字符串，2–4 个短目标，中间用逗号连接，句末用句号；
- 每个分句以「理解」或「学会」起头；
- 不换行、不编号、不写成步骤或段落；
- 屏幕文本，不受 [voice.md](voice.md) 限制。

生成步骤（只读该班两份 `courseware.json`）：

1. 读取每份课件顶层 `title`，以及 `problem_source` 中 `flow_id="flow_1"` 的题干与 `answer_detail`；缺少 `flow_1` 时才使用可用的 `problem_source`。
2. 只提炼这两份课件实际在教的知识点或技能；`title` 里的星级括号（如「（四星）」）去掉后再用。
3. 把提炼结果压成 2–4 个「理解… / 学会…」短目标，连成一句。课件没出现的概念、题型或结论一律不写。
4. 各班型按各自两份课件独立生成。相邻班因共享一星可以部分相近，但不得五班写成同一句，也不得把示例 B 班的句子粘到任何课节。

配星不齐的班型整体不上传，因此不会出现要写空 `learning_objective` 的情况；真遇到两份课件都无法提炼目标，应停止并报告源不足，不能编造。

## `core_method`

1. 对该班实际关联的每份课件，读取 `problem_source` 中 `flow_id="flow_1"` 的题干与 `answer_detail`；缺少 `flow_1` 时才使用可用的 `problem_source`。
2. 归纳该班课件共同或递进的解法骨架：识别关键量、关系、列式或检验方式。
3. 写成简洁、可执行的核心方法，不整段复制解析，不杜撰题目没有的条件或结论。
4. 各班型按各自课件归纳；允许相近，但不得机械写成同一段。

配星不齐的班型整体不上传，因此不会出现 `lesson_data` 为空却要写 `core_method` 的情况；真遇到无课件可归纳，应停止并报告源不足，不能编造方法。

## `begin_guide_data`

- 只写 `tts_text` 与 `audio`，不写 `main_title`、`sub_title`；
- 所有上传的班型内，`tts_text` 必须逐字相同；
- `tts_text` 从当前课节实际课件的主题提炼，必须称呼“同学”，禁止“同学们”；
- `tts_text` 必须是 2–3 句话、100–150 字：依次完成本节主题引入、核心方法提示和学习任务邀请，不用空泛口号凑字数；
- `tts_text` 是逐字口播稿，写法按 [voice.md](voice.md)：数字、分数、算式、单位一律写中文读法，禁用阿拉伯数字、LaTeX 和直角引号「」（`单位1` 写成 `单位一`）；`learning_objective`、`core_method` 是屏幕文本，不受此限；
- `audio` 在文本阶段先写 `""`，媒体阶段用同一份 `tts_text` 调用 TTS 后写入返回的 URL。

示意形状：

```json
{
  "tts_text": "同学，今天我们一起学习<当前课节主题>。我们会先找清题目中的关键量和数量关系，注意题目条件之间怎样一步步连接，再选择合适的方法完成计算或推理。学习时请你边听边圈出重要信息，想一想每一步为什么这样做，最后用自己的话说出解题过程，并检查答案是否符合题意。",
  "audio": ""
}
```

本分册只产生课件关联、学习目标、核心方法和开场，不产生费曼、晋级赛或作业数据。
